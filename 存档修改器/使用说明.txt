《英雄立志传·三国志》存档修改器  v1.2.6
=========================================
适用：存档版本戳 202610020（已在你的 Save0.dat 上实测通过）
用法：纯本地运行、不联网、免安装。双击「2-打开修改器.bat」或直接双击 html。
警告：改之前必须【完全退出游戏】。

v1.2.6 重要修正（修「改出一个两个主角」的问题）：
  · 原因：一个武将（尤其是你自己的自建武将）的记录里，往往存着【不止一个】完整的
      「城市 + 六维 + 三魂点 + 炼魂等级 + 熟练 + 特性」属性块（实测玩家的记录里有 2 个，
      普通武将平均也有 2~3 个）。之前的定位只按「CS10xx 后面跟 6 个整数」找，
      在你的自建武将记录里正好命中了第一个，于是「六维全300 / 三魂拉满 / 熟练拉满」
      只改了其中一个块，另一个块还留着旧值 —— 两个块不一致，游戏里就显示成了两个你。
  · 现在改成：
      1) 候选块必须通过完整签名校验（魂点 0~999999、炼魂 0~99、熟练 0~300、特性 0~9）；
      2) 玩家的块优先选「块里的城市 == 存档头部当前地点」的那个；
      3) 扫描范围限定在本武将记录内（遇到下一条武将记录就停）；
      4) 编辑面板新增勾选项「同时修改该武将的全部属性块」（默认勾上）——
         六维/魂点/炼魂/熟练/特性的改动会同步写到该武将的全部属性块，
         从根本上避免再出现两块不一致。
      5) 面板上会直接列出该武将有哪几个属性块、分别是什么城市，并给警告。
  · 注意：属性块数量 >1 时游戏里可能本来就会显示成多个同名武将（改之前两个块值一样，
    所以看不出来）。勾上同步后两边会保持一致。
  · 如果你已经导出了不一致的存档：重新载入存档 → 选中 ★ 那个自建武将 → 把要改的
    数值再点一遍（勾选保持默认）→ 生成并覆盖，两个块就会被写回一致。

v1.2.5 新增：

    ④ 背包面板里，凡是含魂/技的容器会多一列「魂占用」，并在组标题上显示
    「占用合计 N」（游戏说明：所有配置上阵的魂的占用总和不能超过对应魂点）。
    注意：填了占用筛选后，没有占用值的物品（装备/道具/书籍等）会被自动排除。
  · 「价值」筛选与显示。装备/物品/书籍/动物取 price，魂/技取 value。

  · 批量弹窗的筛选区重排成两行（第一行：分类/关键词/目标组/数量；
    第二行：等级区间、魂占用区间、价值区间），不再挤在一行。

■ 使用步骤
  1. 完全退出游戏
     游戏运行时改无效（退出时会把内存里的数据写回去覆盖掉）。
     可以在任务管理器里确认 ThreeKingdom.exe 已经不在。

  2. 备份
     双击「1-打开存档目录.bat」，把要改的 SaveX.dat 复制一份留底；
     或者载入后点修改器里的「下载原始备份」。

  3. 拖入存档
     把 Save0.dat 拖进页面顶部虚线框。

  4. 改内容（六个面板）
     ② 武将列表（1270 位）：搜索姓名或 ID → 点一行，页面会自动滚到 ③
     ③ 修改：六维 / 资质 / 道德 / 相性 / 出生·登场·死亡年 / 三魂点 /
              三魂炼魂等级 / 武器熟练 / 特性等级
     ④ 背包 / 物品：见下一节，可改数量 / 换物品 / 添加 / 删除
     ⑤ 物品·数值搜索：按 ID 精确定位，或搜数值（金钱、粮草、科技点…）
     ⑥ 与另一份存档对比：列出所有字节差异区，定位字段最省事
     ⑦ 生成并校验新存档 → 下载 → 覆盖回 SaveData 目录（文件名保持原样）

  5. 进游戏查看效果。出问题就用备份覆盖回去。


■ 背包 / 物品（④）
  背包在存档里是【13 个分类容器】，每件物品记作：
      [1字节长度][物品ID][数量 int32][int32][int16]     共 1+len+10 字节
  13 个容器按游戏实际归类，实测映射（跨 20 个存档 100% 一致）：

    组 0   武器            装备 equipType 0
    组 1   防具            装备 equipType 1
    组 2   佩饰            装备 equipType 2
    组 3   坐骑            装备 equipType 3
    组 4   头盔            装备 equipType 4
    组 5   盾牌            装备 equipType 7
    组 6   特殊 / 书籍      装备 equipType 5
    组 7   礼物珍玩         装备 equipType 6
    组 8   地图藏宝图       物品 type 4 / 5 / 6
    组 9   丹药符箓         物品 type 0/1/2/3/15，称号 HTC
    组 10  书籍             SJ 开头的书
    组 11  魂·战技·卡       战魂/辩魂/战法/辩法/战技/武魂
    组 12  材料物资         物品 type 19-32

  能做的操作：
    · 改数量     —— 直接改列表里的数字（不改变文件长度，绝对安全）
    · 换成…      —— 从物品库按名字搜，替换成别的物品（长度可不同）
    · 删除       —— 移除该件
    · ＋ 加入此组 / ＋ 添加物品 —— 新增物品（添加物品会自动按类型归到推荐组）
    · ＋＋ 批量添加（按类型）  —— 见下
    · 全部数量设为… —— 一键把背包里所有物品数量统一设成一个值

  ■ 批量添加（按类型）
    点「＋＋ 批量添加（按类型）」打开，筛选分两行：

      第一行：分类 / 关键词 / 目标组 / 数量
        分类     全部（2784）/ 装备（646）/ 军技（367）/ 物品（335）/ 军魂（306）/
                 称号（303）/ 武技（240）/ 智技（181）/ 书籍（114）/ 智魂（107）/
                 武魂（76）/ 建筑（72）/ 动物（31）/ MOD装备（6）
                 括号里是条目数。军战=军魂·军技，武斗=武魂·武技，舌战=智魂·智技。
        关键词   物品名称或 ID 的片段（可留空）
      第二行：等级区间 / 魂占用区间 / 价值区间
        等级     不限 / ≥0..≥3 与 不限 / ≤0..≤3
        魂占用   不限 / ≥1000..≥8000，只对魂和技有效，填了就只显示有占用值的条目
        价值     直接填数字；装备/物品/书籍/动物用 price，魂/技用 value

      表格里会同时列出 分类 / 等级 / 魂占用 / 价值，方便按需挑。
    然后：
      「全选匹配项」       把当前筛出的全部勾上（表格只显示前 300 行，但全选对全部生效）
      「只选背包里没有的」 先清空，再只勾背包中还没有的
      「反选」「全不选」
      右侧下拉选目标组，或保持「自动（按物品类型归组）」
      数量框填每件数量
    点「添加到背包」→ 会先弹一次确认（告诉你新增几件、文件增大多少），再写入。
    已在背包里的物品会自动跳过，不会重复添加。

    ★ 一次别加太多：容器条数没有硬限制（工具支持到 3000），但游戏侧未必认这么多。
      建议先小批量（比如 10~20 件）加一次、进游戏确认能看到，再放大批量。

  物品库来自游戏自带数据（装备 646 / 物品 335 / 书籍 114 / 动物 31 /
  建筑 72 / 魂·战技·卡 1277，含你那个「新装备」MOD 的物品），
  可以按中文名搜，例如「长剑」「归城仙符」「赤兔」。

  ★ 安全性
    · 「改数量 / 换成别的物品」只覆盖对应字节（换更长的 ID 才会移动后面的数据）
    · 「添加 / 删除」会改变文件长度：工具会把整个背包区段重新序列化并更新容器计数，
      导出前会重新定位背包、逐个容器核对 ID 与数量，并逐字节确认背包区段【之前】
      和【之后】的数据完全没被动过，任何一项不符就拒绝输出
    · 已用你的真实存档做过测试：零改动往返字节完全一致；添加/删除/换 ID 后重解析全部通过
    · 第一次用建议只加 1 件、进游戏确认有效后再批量操作（这是实验性功能）


■ 已精确定位的武将字段（全部用游戏基础表 Hero.json 反查校准过）
  记录锚点 = 武将记录里「ID + 姓名」两串的起点
  资质 6 项             锚点 + ID长度 + 姓名字节数 + 8
  道德                  资质块 + 0x44
  相性                  资质块 + 0x4C
  出生 / 登场 / 死亡年    资质块 + 0x51 / +0x55 / +0x59
  六维 6 项              该武将「所在城市」字符串（CS10xx）之后紧跟的 6 个整数
  三魂点 ×3              六维 + 24
  三魂炼魂等级 ×3         六维 + 36（上限 10）
  武器熟练 ×8            六维 + 48
  特性等级 ×24           六维 + 80

  校准结果（1269 位武将，与 Hero.json 基础值逐项比对）：
    资质        1269/1269 = 100.0%
    出生年      1269/1269 = 100.0%
    登场年      1269/1269 = 100.0%
    道德        1269/1269 = 100.0%
    相性        1269/1269 = 100.0%
    死亡年       804/1269 =  63.4%（差异全是「存档里的值更大」= 游戏内延寿效果）
    六维        1131/1269 =  89.1%（其余是游戏内练高的，存档存的是当前值）


■ 注意事项 / 已知限制
  1. 六维是存档里的「当前值」，和攻略表里的基础值不同（后者是出场初始值）。
  2. 组 2 / 6 / 8 / 10 这四类在你目前的存档里一直是空的，映射是【按类型推断】的；
     如果加了东西游戏里看不到，删掉换一组再试（工具里删/加都很方便）。
  3. 金钱 / 粮草 / 科技点 这些还没有精确定位，请用「⑤ 数值搜索」或「⑥ 对比」来改。
  4. 不要用 ⑤ 面板去改背包里已有的物品 —— 那属于「定点改写」，会被背包重排覆盖；
     如果真这么做了，工具会直接告诉你并拦住你（不会写出坏档）。
     改背包物品请一律用 ④ 面板。
  5. 修改存档属于改单机数据，请自行备份，风险自负。

■ 关于官方 TKEditor.exe
  它其实是【做 MOD 的工具】，不是存档编辑器：工程在 MODProjects\<工程名>，
  导出成 MOD 落到 MODs\<MOD名>。它读取的物品数据来源就是
  ThreeKingdom_Data\StreamingAssets\Json\ 下那些 json（Equipment / Drug / Book …），
  本工具的物品库.js 就是从同一份数据导出的，所以和编辑器里看到的完全一致。
  游戏本体是 Unity IL2CPP，真正能改存档的只有对存档文件本身做二进制处理。


■ 2026-10-08 新增：装配称号（可多个）/ 金钱 / 策略点 / 科技点
  位置：面板 ⑦。

  【装配称号】游戏称号面板里生效的那些（可不止一个）。载入档后自动列出，
    每条可「换成所选 / 删除」，下方搜索选中称号后可「添加到装配列表」。
    原理：称号存在玩家资产块的 [数量][长度+ID]… 列表里（金钱第二副本前 2 页内），
    增删会插入/移除字节并同步数量，与背包加物品同一原理。
    生成后请进游戏验证一次读档与称号生效。
    已实测确认的定位（Save2_最新_1008）：万人之雄 / 大召唤师(MOD) / 太平使者 / 天下极策。

  【展示称号】魂/装备装配列表里的那个 HTC 位（等长替换，不改变文件长度）。

  【金钱】存档里有双份：文件头部（玩家名之后）+ 玩家资产块，写入时两处一起改。
  【策略点 / 科技点】在家族块里：科技点紧跟 JZ 建筑列表，策略点在其后、家族表头之前。
    面板会显示「当前值」，请和游戏里对一眼，对得上再改。
    实测定位（Save2_最新_1008）：策略 555 @0x15697e8，科技 1168 @0x1569021，金钱 9818508 @0x27+0xd620f0。

  【更新物品库.js】装了新 MOD / 搜不到某物品称号时，运行：
    python "C:\Users\kinch\.workbuddy\skills\update-item-catalog\update_item_catalog.py"
    会自动合并主游戏 JSON + MODs 下所有同名表（称号带 HTC 前缀），
    重新生成物品库.js（当前 2785 条，其中称号 304 条，含 MOD 称号「大召唤师」）。

■ 2026-10-10 重要修复：新版本存档「加物品看不到 / 读档崩」的根因
  【症状】用 1.0.9 之后（版本戳 202610091）的存档改背包，加进去的东西游戏里看不到，

    于是整条**真背包被判为非法**，工具退而求其次，在别处找到了一个「长得像背包」的结构当成了背包 ——
    你的增删改其实全都写到了那个假结构上。

  【修复】
    · 去掉 f2 的上下限校验（它本来就是自由字段）。
    · 定位时不再「找到第一个像背包的就算数」，而是要求候选足够大（≥250 件、≥10 个非空组）才提前收工，

  【验证】三种版本戳（202610020 / 202610060 / 202610091）的存档全部正确定位到真背包
    （305~369 件、11 个非空组、耗时 31~368 ms）；不改任何东西时往返输出与输入 0 字节差异。

  【说明】之前你在旧版本存档上加物品一直是好用的 —— 是更新到新版本后才踩到这颗雷。

■ 2026-10-13 追问：制造书里有 MOD 装备的吗？—— 目前没有，原因在 MOD 数据本身
  【结论】物品库里 128 条制造书全是主游戏装备的，**没有 MOD 装备的**。
  【为什么】制造书是游戏按「装备是否需要制造书解锁」生成的，判据是装备表里的 forgeUnlockType：
    · forgeUnlockType = 1 → 需要制造书（实测：山纹银狮甲 属于这类，游戏里确实有它的制造书）
    · = 0 / 2 → 不需要制造书，游戏不生成

      逆鳞龙胆枪   ft=0  有配方（紫金×3、千年铁木×3、陨铁×3、秘银×3）

    只是没有对应的制造书。

  【想要 MOD 装备也有制造书？】两条路：
    A. 正规做法（推荐）：改 MOD 的 Equipment.json —— 把想做的装备 `forgeUnlockType` 改成 1
       （没配方的再补上 `material`），游戏就会为它们生成制造书；
       然后跑一次「更新物品库」，制造书会按 `FORGEWP + 装备编号` 自动进库。
       （生成脚本已支持 MOD 的字母编号，如 WP10001ouia1 → FORGEWP10001ouia1。）
    B. 只先让工具里能选到：按命名规律硬加 6 条 FORGEWP1000xouia1 进物品库 ——
